# nenrin-core

NENRIN の記録コアと検証ロジック。

[NENRIN](https://nenrinapp.com) は、制作ツール上の作業過程を記録し、作品がその過程を経て生まれたことを第三者として証明するサービスです。このリポジトリは、その中核である**記録**(作業過程のハッシュチェーン化と外部アンカー)と**検証**の実装を Apache License 2.0 で公開しています。NENRIN のデスクトップアプリとサーバーは、この技術の上に作られています。

## パッケージ

| パッケージ | 内容 |
|---|---|
| [`packages/record-core`](./packages/record-core/README.ja.md) | 記録エンジン、ハッシュチェーン、鍵、検証、要約、年輪カード描画、制作ツール別アダプタ、OS アダプタ。JavaScript(ESM)、依存パッケージなし |
| [`packages/verify-core`](./packages/verify-core/README.ja.md) | サーバー側の検証ロジック。提出されたチェーンとアンカーの受領記録を検証し、`WorkSummary` を導出する。TypeScript |

## 設計の要点

- **ローカルファースト**: 記録は端末内に保存されます。記録中に外へ出るのはチェーン先頭のハッシュとその署名だけで、記録本体が送られるのは本人が発行の操作をしたときに限られます。通信の全一覧は [NETWORK.md](./packages/record-core/NETWORK.md) にあります
- **ハッシュチェーン**: 各イベントは直前のイベントのハッシュを含みます。途中のイベントを差し替えると以降のハッシュが一致しなくなり、検証で検知されます
- **外部アンカー**: チェーン先頭のハッシュを定期的にサーバーへ預け、受領時刻とサーバー署名を受け取ります。鍵とローカルデータを持つ本人がチェーン全体を作り直しても、サーバー側の受領記録と食い違うため検知できます
- **二系統の検証**: 内部整合性(構造・ハッシュ・本人署名。ローカルだけで再計算できる)と、外部突合(受領記録との一致・サーバー署名)を分けて報告します
- **アダプタ**: 制作ツールごとの違い(前面アプリ名、作品ファイルの判定、ハッシュの取り方、統計)はアダプタに閉じ込め、エンジンはツールを知りません

## 証明の範囲

NENRIN が証明するのは「対象ツール上で制作の過程があったこと」です。「AI を一切使っていない」「人間が創作した」といった断定はしません。この方針はスキーマ・検証結果・表示文言まで一貫させており、このリポジトリのコードもその範囲を超える主張を持ちません。記録データは本人が発行するまで端末の外に出ず、AI の学習には使いません。

## 想定する利用

- 新しい制作ツールのアダプタを書き、その作業過程を記録する
- 独自のアンカーサーバーと組み合わせて運用する(`createRecorder({ server })`)
- 提出された記録の検証を自分のサービスに組み込む(`verify-core`)
- 記録形式と検証手順を読み、NENRIN の証明が何に基づいているかを確かめる

## 始め方

Node.js 22 以上が必要です。npm レジストリには公開していないため、リポジトリを取得してローカル依存として参照してください。

```sh
git clone https://github.com/nibura2002/nenrin-core.git
cd nenrin-core/packages/record-core
npm test                                          # 外部に接続しません
npm install ../nenrin-core/packages/record-core   # 別プロジェクトから使う場合
```

使い方は各パッケージの README を参照してください。
